# Action: motion-design

Loaded by `SKILL.md` when the requested action is `motion-design`. Craft a motion video from zero: interview the user until the idea is concrete, shape it on a proven recipe, lock a storyboard with its song timing, compose ElevenLabs music and lyrics to that timing, then build it as web animation with [HyperFrames](https://github.com/heygen-com/hyperframes) (optionally mixed with Blender renders) on the measured song. Most video tools start from a formed brief; this action exists to form it.

## Boundaries

- Use when the user wants a new motion video, title sequence, reel, music video, greeting, explainer, or other animated piece, whether the idea is blank or half-formed.
- Do not use for a specific operation on an existing HyperFrames project (render, lint, diagnose, edit one scene): load the HyperFrames skills directly. Do not use for live-action editing or footage grading.
- External skills are linked, never copied. Read each one from its link, or its installed copy, at the step that needs it. If a needed external skill or CLI is missing, name the install command from its own documentation and ask the user before installing anything.
- The workflow writes no Python. Use the HyperFrames CLI, the ElevenLabs CLI or JavaScript SDK, and Blender's command-line flags; when a step seems to need a helper script, write it in JavaScript or TypeScript.
- Media sourced from the web or generated by a provider gets its rights and provenance recorded through the `track` action; never assume a found image is free to use.

## Inputs and output

- **Required**: the user's request, however vague.
- **Optional**: goal, destination, length, references, supplied media, brand, song, lyrics, and any explicit "just build it" signal.
- **Output**: a HyperFrames project containing `BRIEF.md`, `STORYBOARD.md`, the compositions, the music track, the draft page, and the rendered video; asset and render entries recorded through `track`.

## Workflow

Each step names the file that owns it. Read a file only when its step begins, and read only the recipe shelf the chosen concept uses, so the working context holds the current step rather than the whole library.

1. **Ask the direction questions** in [interview](directions/motion-design/interview.md): goal, platform, materials, format, mood, and the subject when a real person, pet, or brand figure is on screen.
2. **Draft five concepts** following [concept](directions/motion-design/concept.md): define the serving, choose what drives the piece, and fill five different recipes or story devices with the user's facts. When the sound could lead (a supplied song, fixed narration, or lyrics that must be sung), settle what leads with [music](directions/motion-design/music.md#decide-what-leads) here, before any concept is timed.
3. **Confirm on a board** as [interview](directions/motion-design/interview.md#board) describes: style directions, the five concepts as storybook slideshows, and sound, then character styles in the chosen look. Each round demonstrates only the choice it asks for.
4. **Approve the storyboard and the song's timing** following the [storyboard template](templates/storyboard.md): the arc from the chosen recipe, shot list on a bar grid, sync points, style sheet, catchphrases written with [hooks](directions/motion-design/hooks.md), and the music plan, which gives every section its time window, tone, rhythm, and lyrics. Present it as a [slideshow](directions/motion-design/interview.md#slideshow) of its frames and get approval through the question tool; revise until approved. A revision is not an approval. The approved music plan is the song's specification, so the song is generated to the story rather than the story refitted to a song. For a piece longer than about a minute or with a story to follow, play the slideshow at the planned pace to a fresh viewer first, as [quality](directions/motion-design/quality.md) describes, because a confusing beat is cheapest to fix before it is animated.
5. **Set up the project.** Follow the `hyperframes` entry skill: run `npx hyperframes init`, then write `BRIEF.md` in the [HyperFrames brief format](https://github.com/heygen-com/hyperframes/blob/main/skills/hyperframes/references/brief-format.md) with `workflow: general-video`, `flow: companion`, `storyboard: yes` for a picture-first piece, or `workflow: music-to-video` when the user supplied the song. Write the approved storyboard as `STORYBOARD.md` in the [HyperFrames storyboard format](https://github.com/heygen-com/hyperframes/blob/main/skills/hyperframes/references/storyboard-format.md) so HyperFrames asks no intent question again.
6. **Compose the song to the approved timing.** Follow [music](directions/motion-design/music.md): generate takes from the approved plan, let the user pick by ear, measure the accepted take, and lock its times into the timing data object. Repair a take that drifts or drops a planned section before any picture exists, so the picture is built once, on measured times.
7. **Build the picture** on the locked timing through the `hyperframes-core` and `hyperframes-animation` skills, following [build](directions/motion-design/build.md). Use [Blender](directions/motion-design/blender.md) only for shots the storyboard marks as 3D beyond what Three.js in HyperFrames can deliver.
8. **Confirm a draft.** Follow [render](directions/motion-design/render.md#draft): check every sync point and text exit on snapshots, render a 1 fps draft, and show it with the song as a standalone HTML page. The user confirms it through the question tool before the full render.
9. **Render and finish.** Follow [render](directions/motion-design/render.md#full-render): render once at 25 fps, watch it with sound, and apply the finish test for its form in [quality](directions/motion-design/quality.md) before calling it done. When the platform needs captions, deliver a caption file from the measured word times; animated keywords are not captions. Package the title, cover frame, caption copy, and any cut-downs around the same promise with [payoffs](directions/motion-design/payoffs.md#package-the-same-promise).
10. **Record and review.** Register supplied, sourced, and generated assets and the render through the `track` action. Route the user's feedback on the render through the `review` action; each feedback round produces a new render revision.

## Verification

- Every question the request clearly answered was skipped; every answered question appears in the ledger with the user's wording.
- The approved storyboard, `BRIEF.md`, and `STORYBOARD.md` agree on message, platform, aspect, length, and arc.
- The song was generated from the approved music plan, and its measured times were locked before the picture was built.
- Every sync point in the storyboard lands within the [music](directions/motion-design/music.md) tolerance of its measured beat or word in the final render.
- The full render ran after the user confirmed the draft page, and its trace shows the worker count [render](directions/motion-design/render.md#full-render) sets.
- No external skill text was copied into the project or this repository; no Python file was written.
- Every sourced or generated asset has provenance and rights recorded, or is reported as pending.

## Completion

Report the confirmed brief, the chosen style direction, character style, story concept and its recipe code, the catchphrases, the project path, the draft page, the render path and its revision, sync-point results, assets still pending rights or hashes, and the next action for the user.
