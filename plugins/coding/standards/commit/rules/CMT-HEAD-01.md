# CMT-HEAD-01: Match the Canonical Header Regex

## Severity

error

## Intent

Every commit message header is `type(scope)!: subject`, matching the canonical
regex in [write.md](../write.md) with a type drawn from its closed allowlist.
The header is the only machine-parsed part of the message: changelog
generation, release versioning, and history search all read it. A header that
fails the regex is not a style deviation; it is unparseable.

## Scan

Match the exact subject string that will be written — not a paraphrase of it —
against the regex, before the mutation runs. Then confirm the type appears in
the allowlist table; a repository policy may narrow that list but never widen
it.

## Fix

Rewrite the header before the mutation. Do not commit and reword afterwards:
the invalid header still enters any history that is pushed or shared in the
interval. If no allowlisted type fits, the change is doing more than one thing —
split it.

## Edge Cases

- `revert` requires the `Reverts <sha>` body line owned by `CMT-BODY-02`.
- A merge commit generated by the VCS is not authored through this standard.
- A type that merely looks conventional (`feature`, `bugfix`, `hotfix`) is not
  in the allowlist and there is no alias path.
