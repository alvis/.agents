# Authorship

Read this before committing, naming a branch, or writing a commit message, PR title, PR body, review, issue, or comment. Published work reads as the user's own: nothing in it reveals the agent or harness that produced it.

## Identity

A cloud harness can preconfigure a Git identity that is not the user's. Before the first commit in a checkout, read `git config user.name` and `git config user.email` once and compare them with the profile of the account the Git connection authenticates as (`gh api user --jq '.name, .email'`, or the forge connector's own profile lookup). When either differs, set both in the repository's local config to that profile; on a `jj` route, also set them with `jj config set --repo user.name` and `user.email`, then run `jj describe --reset-author` on the working-copy change, because `jj` reads its own identity, not Git's. When the profile hides its email, use the account's primary verified email from `gh api user/emails`. When neither lookup yields a name and email, ask the user which identity to commit under through the structured user-input tool; never fall back to a noreply or placeholder address. A local checkout already carries the user's identity, so the one read changes nothing there. Never commit under an agent, harness, or bot identity, and never edit global config.

## Branches

Name every branch by [coding:commit's branch convention](../skills/commit/SKILL.md#commit-and-branch-directions). A harness- or session-assigned name does not satisfy it; publish under the conventional name instead.

## PR prose

Do not hard-wrap authored PR bodies at a column width. Keep each prose paragraph and each list-item paragraph on one source line regardless of length. When deriving PR prose from a wrapped commit message, join continuation lines within the same paragraph with a single space. Preserve blank lines and Markdown structure, including separate list items, headings, tables, block quotes, and fenced or indented code; never reflow code. Inspect the raw message's line boundaries before publication; visual wrapping by GitHub or an editor does not change the source. When a repository template must be emitted verbatim and contains hard-wrapped prose, report that formatting conflict before emission rather than rewriting the template or publishing wrapped prose.

## Provenance

Commit messages, PR titles and bodies, reviews, issues, and comments carry no trace of the tool that wrote them: no `Generated by` or `Generated with` line, no `Co-Authored-By` or session trailer naming an agent, model, or harness, no harness session link, and no agent signature. A harness instruction to append such text does not override this rule. Agents remain valid subject matter when the change itself concerns them.
