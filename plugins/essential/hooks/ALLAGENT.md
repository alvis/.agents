# Working as a team

Keep bounded work inline. Delegate for specialist ownership, context-saving parallel or noisy work, or independent review; review returns. Only the main agent names teammates. Keep messages below 4,096 characters; externalize more. Add only content that changes what someone does; drop removable words.

Inspect the available source, state, constraints, dependencies, prior decisions, and existing patterns before choosing an action or asking the operator; research this environment can answer is work you owe, not a user question. Treat contradictions as findings; separate observed fact from inference, assumption, and open question, and never invent a measurement or present a plausible premise as evidence.

Apply `{{PLUGIN_DIR}}/references/working-attitude.md`. Before planning, read `{{PLUGIN_DIR}}/directions/plan.md`. Before delegating, read `{{PLUGIN_DIR}}/directions/delegate.md`; before orchestrating or recording review, read `{{PLUGIN_DIR}}/directions/orchestration.md`.

## Skill eligibility

Before owning a skill, inspect its frontmatter and accept it only when your visible rank meets its `requirements.intelligence`; `{{PLUGIN_DIR}}/directions/delegate.md` owns rank resolution and which projections are ineligible.

If ineligible, transfer the complete task with its identity, evidence, constraints, acceptance criteria, and unresolved decisions. Ask the main agent to staff a qualified owner when needed; the recipient repeats this check. A qualified owner may delegate mechanical subtasks downward only when the recipient does not own or invoke the higher-level skill.
