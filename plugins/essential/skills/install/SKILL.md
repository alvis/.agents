# Install

Install this marketplace's agent templates and, only in Grok Build, attach its startup bootstrap. Bash and Bun must be available. This skill configures an already available Essential plugin; acquiring or enabling marketplace plugins belongs to the harness's plugin manager.

## Select the harness

Use the active runtime: `claude`, `codex`, or `grok`. Determine it from the session, not from installed directories or a plugin-root variable inherited from another harness. In OpenCode, report that its V1 projector owns installation; do not run these native installers or change Grok configuration.

Resolve `scripts/install.sh` from the directory containing this loaded `SKILL.md`; ordinary shell commands need not receive hook environment variables.

## Install or refresh

Run the resolved script with `--harness` set to the active runtime:

```bash
bash "<loaded skill directory>/scripts/install.sh" --harness grok
```

Replace `grok` with `claude` or `codex` for those runtimes. Use `--destination <absolute-agent-directory>` only when the user selected a custom agent directory. Default destinations are `~/.claude/agents`, `${CODEX_HOME:-$HOME/.codex}/agents`, and `${GROK_HOME:-$HOME/.grok}/agents` respectively. A custom agent destination does not relocate Grok's user configuration.

The installer validates and stitches the discovered templates before changing files. Claude and Codex discovery uses source-checkout siblings or enabled same-marketplace plugins; repeatable `--include-marketplace <name>` arguments add only marketplaces the user explicitly trusts. Grok resolves effective enablement and paths from `grok inspect --json`, including when Essential is loaded from a checkout. Discovery failures must be corrected; do not substitute a scan of installed directories.

Agent metadata and harness overlays remain authoritative. Claude receives Markdown, Codex receives TOML, and Grok receives Markdown with its supported model and effort settings. The installer also supplies the shared support files those agents need.

<IMPORTANT>
Only the Grok branch attaches a marked instruction to read and follow `@<absolute-path>/GROK.md` in `${GROK_HOME:-$HOME/.grok}/AGENTS.md`. It preserves other content and refreshes its own unchanged block on reinstallation. Claude and Codex installation never reads or writes that file.

Installation records owned paths and hashes under the selected agent directory's `.essential/`. Existing unowned content that differs from the generated bytes, modified owned files, and conflicting attachment ownership stop installation before changes. Resolve the reported conflict with the user; do not overwrite it manually or remove its ownership record to bypass the check. Byte-identical generated files may be adopted.
</IMPORTANT>

Reinstallation updates unchanged owned files and removes unchanged files no longer generated. It preserves edited former agents and their support files. Failed operations roll back their changes. If recovery itself fails, preserve the reported recovery files and report the incomplete operation.

## Verify and report

Require a successful installer exit and inspect its reported destinations and installed count. Check one emitted agent definition in that destination. For Grok, also inspect the managed `AGENTS.md` block and confirm its absolute bootstrap path exists.

Start a fresh session to load the new agent definitions. In Grok, `grok inspect --json` must list the user `AGENTS.md` among its project instructions; a fresh session must then read the bootstrap and the applicable enabled-plugin payloads. A successful file write alone does not prove model compliance.

Report the harness, installed count, agent destination, Grok attachment outcome when applicable, and any preserved conflicts or recovery paths. Use `essential:uninstall` to remove this installation's unmodified managed files and Grok attachment; never suggest deleting the entire agents directory.
