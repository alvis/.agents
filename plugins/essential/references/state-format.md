# Typed state format

Operational state is a linked MDC graph under `.state/`. The executable
`essential.state/v1` interfaces and JSON Schema generated by
`scripts/state-model-v1.schema.ts` are the sole field, enum, and requiredness
authority. This document owns the human writing and lifecycle rules.

## Document contract

Every `.mdc` document begins at byte zero with frontmatter:

```md
---
schema: essential.state/v1
kind: stream
ref: state:agents:work:eng-421
workId: eng-421
---
```

Child documents also declare `workRef`. Every semantic block has a known
`type` and globally unique immutable `ref`. Annotation keys use the domain
model's camelCase field names and contain machine data; visible content holds
human prose. Nested blocks express containment only. Dependencies, evidence,
records, and document ownership use explicit refs.

Opening and closing refs must match. Indent nested blocks by two spaces and do
not detach them with a blank line. `state.source` blocks carry POSIX relative
`.mdc` paths. Unknown schemas, kinds, entity types, fields, enum values, and
malformed annotations are errors.

Refs use these stable families:

```text
state:<project>
state:<project>:work:<work-id>
state:<project>:work:<work-id>:task:<ID>
state:<project>:work:<work-id>:sc:<n>
state:<project>:work:<work-id>:event:<revision>-<sequence>
```

Refs are never renamed or reused. Links cannot leave `.state/`, cross work
ownership, traverse symlinks, form cycles, or dangle. A graph may contain only
one schema version.

## Canonical graph

```text
.state/
├── overview.mdc
├── environment.mdc
├── traps.mdc
├── works/<work-id>/
│   ├── state.mdc
│   ├── goal.mdc                 # only when charterStatus is not absent
│   ├── lease.json
│   ├── state/{working,journal,revisions,unresolved}.mdc
│   ├── {proposals,changes,decisions,design,review}.mdc
│   ├── children/*.mdc
│   └── artifacts/**
└── archive/<work-id>/...
```

`lease.json`, migration receipts, and native files under `artifacts/` retain
their native formats. No lifecycle reader treats Markdown as state. A resolver
that finds legacy Markdown returns `migration_required`; only Doctor's approved
migration may replace it.

## Authority and revisions

When `charterStatus` is not `absent`, `goal.mdc` owns the charter,
requirements, boundaries, success criteria, specification locators, and
repository anchors, and `state.mdc` carries its typed source link. When
`charterStatus` is `absent`, neither the document nor that source link exists;
the missing charter must be authored and approved before execution. Pending
specification fields belong to a present charter and do not change this rule.
`state.mdc` owns the stream,
phase, plan and state revisions, task registry, continuation, records, review,
submission, completion, and links to detail documents. Detail documents refine
those entities without redefining them.

Plan revisions change approved task definitions or edges. State revisions are
monotonic and advance on every main-agent graph write. A plan revision appends
a revision entity naming what changed, why, approver, and accepted specification
base. The root document is the graph commit point and is written last.

## Tasks and lifecycle

Task IDs are immutable. Top-level IDs match `^[A-Z]{3}$`; children append
`01` through `99`, with one child level. Dependencies form a DAG. A parent is a
derived roll-up; leaves are executable. Preserve the statuses `planned`,
`working`, `done`, `failed`, `blocked`, and `cancelled` and their existing
dependency, retry, unblock, requiredness, ownership, evidence, and acceptance
semantics.

`done` is terminal history. Changed evidence never reopens it: attach
`validity: { state: "stale" | "unknown", reason }` and create a new remediation
task. Omitted validity means current.

Stream phases are `planned`, `working`, `reviewing`, `completed`, and
`archived`. Blockers remain independent of phase. `reviewing` requires every
required leaf done and an applicable submission. `completed` additionally
requires observed landing or acceptance, durable promotion or an evidenced
`not required` disposition, and an owned disposition for every item that
outlives the stream.

## Events and records

Journal events are append-only typed entities. Each records an ISO-8601 time,
actor capability, state revision, event type, subject ref, transition or
summary, and optional evidence and invalidations. Event types are `status`,
`decision`, `revision`, `sync`, `sweep`, and `lease`. Bulk migration and
backfill use `sweep`; they never impersonate progress.

Proposal, change, decision, design, review, finding, submission, and completion
entities preserve provenance, supersession, effects, evidence, ownership, and
recheck conditions. Accepted decisions are superseded, never rewritten.

## Validated writes

The main agent is the sole graph writer and holds the stream lease. A worker
returns task, event, evidence, and invalidation deltas. The writer:

1. builds the complete changed graph in a staging directory;
2. decodes and validates it through the shared state codec;
3. compares immutable refs, task definitions, monotonic revisions, terminal
   statuses, and append-only events with the current graph;
4. invokes the lease-verified `state-write` path with the staged directory;
5. commits children first and `state.mdc` last.

Any failure leaves the previous root authoritative. Never write a child in
place before the staged graph passes. Every lifecycle reader uses the same
decoder and validator before acting.
